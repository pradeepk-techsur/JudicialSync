<objective>
Fill the eight slots Phase 4 said it would fill, with panel-sized wrappers that point at the
existing screens, gated by the entitlement each one actually requires.

Purpose: CONTEXT locks exactly what Phase 4 registers — **"Admin (configuration, identity/entitlement
admin, reporting, adapter health); Judge/Chambers (case timeline, approval-type tasks); Clerk
(exception queue, work queue); Deputy (nothing)"** — and how: **"A workspace slot registration
points at an existing component (or a panel-sized wrapper of it) … Phase 4 is purely additive here —
no route changes, no Playwright URL rewrites, no axe regressions on screens that already passed."**

The entitlement on the registration is the point. F11's validation clause — *"No workspace may
expose an action the user's role/entitlement does not permit merely because the component is
present"* — is satisfied structurally because the gate is a required field on the registration, not
a condition someone remembered to write inside a component.

Deputy registering nothing is a deliverable, not an omission. CONTEXT: *"Shell only … with the F17
slot declared and empty"*, and **"Do NOT build the keyboard-shortcut registry, focus-management
harness, or touch-target system. That is interaction machinery for a task that does not exist."**

Output: eight panels, their registrations, the application-start import, and the browser proof that
composition and entitlement gating both work.
</objective>

**`02-UI-SPEC.md` is binding.** The rules that bite hardest here:
- **One primary per page-level region, and repeating cards get zero.** A workspace home is one page
  region holding up to six panels. No panel renders a `usa-button` primary; footer links are links
  or outline buttons.
- Accent is reserved for the listed four uses. Panel headings, card borders and status Tags are not
  among them.
- Every status Tag declares its foreground pairing; colour is never the only indicator —
  icon plus text plus colour (`Y2-accessibility.md` 1.4.1). Reuse plan 03-15's `AgingIndicator` and
  plan 03-15's `SeverityTag` rather than writing new indicators.
- **D-2 / D-11, still awaiting adjudication:** a conditionally-blocked control uses `aria-disabled`
  plus a no-op handler plus permanent visible helper text, never the `disabled` attribute. The
  separation-of-duties block on Screen-15 is exactly this case.
- **D-1, still awaiting adjudication:** USWDS 3.x ships no Tabs component. **No panel in this plan
  uses a tab strip** — Screen-04, 10 and 15 are all card stacks. If one is later wanted, reuse the
  contract's `ConfigSectionTabs` decision rather than inventing a second approach.

**Do not build here:** any new screen, any new route, any change to an existing page component, any
Phase 5–8 panel, any Deputy interaction machinery, any portfolio or custody surface.

`h1` is the page title), body, and an optional footer link rendered as a text link or an
`usa-button--outline`. Never a primary button — put the one-primary rule in a comment with the
reason, since a panel author reaching for emphasis is the obvious way it gets broken.

Each panel below renders a **compact summary plus a link to the standalone screen**, consuming the
`compact: boolean` prop `PanelProps` declares. That resolves CONTEXT's discretion item *"whether a
panel renders differently in-workspace (compact) versus at its standalone route (full)"*: the
standalone screens are untouched and the panel is a small, separate summary component. Re-rendering
a full screen inside a card would make every workspace home a heavyweight page and would couple the
panel to the screen's internal layout.

Data comes from the **existing endpoints** through the generated client and TanStack Query. Add no
new API.

**`AdminConfigurationPanel.tsx`** — slot `admin.configuration`, entitlement: the configuration key
plan 02-13's nav item uses (read it; do not invent). Renders the court's currently effective rule

**Read-only.** It lists pending privileged items from `GET /entitlements/requests?status=pending`

subject, entitlement, age via `AgingIndicator` — **with no action control**, because Phase 1

Screen-15 specifies it: *"Self-drafted approval pending → 'Review & Approve' explicitly disabled for
