<objective>
Create the entire `platform` PostgreSQL schema, the database roles, the grant posture that makes
immutability structural rather than conventional, and the hash-chain verification trigger.

Purpose: Phase 1 success criterion 3 says an attempt to UPDATE or DELETE a past audit row must fail
"at the database grant level, not merely via application convention."
`TechArch/02a-data-shared.md` §5 opens with that as a **binding** statement, and
`TechArch/04-security.md` §7.3 explains why: "PostgreSQL itself will reject the statement regardless
of which code path generated it, including a compromised application process or an operator using
the application's own credentials." That guarantee is created here or not at all — every later plan
inherits it. CONTEXT extends the same posture to the case model: "the application database role
holds **no DELETE grant** on these tables — the same enforcement posture as the audit table."

Output: `prisma/schema.prisma` covering the whole platform schema, three ordered SQL migrations
(tables → grants → hash chain), the two-role connection model, and tests that prove a privileged
write is refused by Postgres rather than by TypeScript.
</objective>

<feature_dependencies>
Implements: F0: Identity and Access Management (users/roles/user_roles/scope_assignments/sessions), F1: Core Case and Docket Data Model (courts…security_designations), F2: Audit Trail and Audit Explorer (append-only hash-chained audit_events), F13: Security and Compliance Baseline (file_references, malware_scan_results, security_policies, retention_schedules, disposition_log)
Depends on: None at the feature level — this is the data substrate
Enables: F2: Audit Trail and Audit Explorer (the chain trigger is what makes "tamper-evident" true)
</feature_dependencies>

Plus one Phase 1 addition the chain needs — a single-row chain head so `prev_hash` sequencing is
serializable rather than racing on `MAX(occurred_at)`:

```sql
CREATE TABLE audit_chain_head (
  id BOOLEAN PRIMARY KEY DEFAULT true CHECK (id),
  last_row_hash TEXT NOT NULL,
  last_audit_event_id UUID,

INSERT INTO audit_chain_head (id, last_row_hash)
```

`TechArch/04-security.md` §7.3 defines the chain:
`row_hash[n] = SHA-256( canonical_json(row[n] minus row_hash) || row_hash[n-1] )`, and requires that
"A `BEFORE INSERT` trigger recomputes the expected hash server-side and rejects the insert if the
application-supplied hash doesn't match — this prevents a compromised application instance from
forging a consistent-looking chain."

Define the canonical payload as an **ordered, pipe-delimited string over the named audit columns**,
with `jsonb` columns rendered by Postgres' own deterministic `jsonb::text` output. A whole-row
`to_jsonb()` is deliberately avoided: it would include `id` and `row_hash` and would silently change
meaning the moment a later phase adds a column, breaking every historical chain. Pin the field list.

```sql
CREATE OR REPLACE FUNCTION platform.compute_audit_row_hash(
  p_actor_id UUID, p_action_type TEXT, p_object_type TEXT, p_object_id UUID,
  p_before_state JSONB, p_after_state JSONB, p_rule_version_ref UUID,
  p_calculation_version_ref UUID, p_client_ip TEXT, p_session_id UUID,
  p_occurred_at TIMESTAMPTZ, p_prev_hash TEXT
) RETURNS TEXT LANGUAGE sql IMMUTABLE AS $$
  SELECT encode(digest(convert_to(
      coalesce(p_actor_id::text, '')               || '|' ||
      coalesce(p_action_type, '')                  || '|' ||
      coalesce(p_object_type, '')                  || '|' ||
      coalesce(p_object_id::text, '')              || '|' ||
      coalesce(p_before_state::text, '')           || '|' ||
      coalesce(p_after_state::text, '')            || '|' ||
      coalesce(p_rule_version_ref::text, '')       || '|' ||
      coalesce(p_calculation_version_ref::text,'') || '|' ||
      coalesce(p_client_ip, '')                    || '|' ||
      coalesce(p_session_id::text, '')             || '|' ||
      to_char(p_occurred_at AT TIME ZONE 'UTC', 'YYYY-MM-DD"T"HH24:MI:SS.US"Z"') || '|' ||
      coalesce(p_prev_hash, '')
    , 'UTF8'), 'sha256'), 'hex');
$$;
```

The trigger enforces three things — supplied hash correctness, chain continuity, and chain-head
advancement — under a transaction-scoped advisory lock so concurrent audit writes serialize instead
of forking the chain:

```sql
CREATE OR REPLACE FUNCTION platform.audit_events_hash_chain_guard()
RETURNS TRIGGER LANGUAGE plpgsql AS $$
DECLARE v_head TEXT; v_expected TEXT;
BEGIN
  PERFORM pg_advisory_xact_lock(hashtext('platform.audit_events'));
  SELECT last_row_hash INTO v_head FROM platform.audit_chain_head WHERE id;

  IF NEW.prev_hash IS DISTINCT FROM v_head THEN
    RAISE EXCEPTION 'AUDIT_CHAIN_BROKEN: prev_hash % does not match chain head %', NEW.prev_hash, v_head
      USING ERRCODE = 'integrity_constraint_violation';
  END IF;

  v_expected := platform.compute_audit_row_hash(
    NEW.actor_id, NEW.action_type, NEW.object_type, NEW.object_id,
    NEW.before_state, NEW.after_state, NEW.rule_version_ref,
    NEW.calculation_version_ref, NEW.client_ip, NEW.session_id,
    NEW.occurred_at, NEW.prev_hash);

  IF NEW.row_hash IS DISTINCT FROM v_expected THEN
    RAISE EXCEPTION 'AUDIT_CHAIN_BROKEN: supplied row_hash does not match server recomputation'
      USING ERRCODE = 'integrity_constraint_violation';
  END IF;

  UPDATE platform.audit_chain_head
     SET last_row_hash = NEW.row_hash, last_audit_event_id = NEW.id, updated_at = now()
   WHERE id;
  RETURN NEW;
END $$;

CREATE TRIGGER trg_audit_events_hash_chain
  BEFORE INSERT ON platform.audit_events
  FOR EACH ROW EXECUTE FUNCTION platform.audit_events_hash_chain_guard();
```
