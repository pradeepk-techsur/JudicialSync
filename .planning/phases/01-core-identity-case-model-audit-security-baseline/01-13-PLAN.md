<objective>
Ship the thin USWDS shell: a real browser login through Keycloak with TOTP, one generic
authenticated application frame, the generated API client, and the release-blocking accessibility
gate.

Purpose: CONTEXT explains why any UI ships in Phase 1 at all — "it establishes the USWDS build, the
generated OpenAPI client, and the accessibility gate early, so Phase 4 extends a working shell
rather than absorbing the entire frontend toolchain risk." And it bounds the UI tightly: "**One
generic shell — no role-specific layouts.** A single USWDS header/nav/content shell used by
everyone; what differs by role is only *which data and nav items appear*, driven by entitlements.
**Per-role workspace designs stay entirely in Phase 4.** … Building even one role-specific view as a
'proof' was explicitly rejected."

The accessibility gate is equally non-negotiable: "axe-core runs in CI from Phase 1 and **blocks the
build** on violations … Report-only was rejected — a warning nobody must act on gets ignored, and
PROJECT.md calls Section 508 'non-negotiable, not optional polish.'"

Output: the OpenAPI contract and generated client, the `apps/web` application with login and shell,
the `web` Compose service behind the existing TLS origin, and the CI accessibility gate.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-01-55 | Elevation of privilege | A user editing client state or calling the API directly to act beyond their entitlements, because the UI was treated as the control | mitigate | `AuthProvider.hasEntitlement` is documented and used **only** for rendering; every API route is independently evaluated by the PDP guard (plan 01-07). `apps/web/e2e/login-shell.spec.ts` case 4 verifies the UI gating, while plan 01-14's suite bypasses the UI entirely and asserts the server refuses. |
| T-01-56 | Information disclosure | Secrets or internal service addresses baked into the client bundle | mitigate | The client calls the same-origin relative path `/api/v1`; no `OIDC_CLIENT_SECRET`, `S3_ENDPOINT`, `minio:9000`, or `INTERNAL_SERVICE_TOKEN` is referenced in `apps/web/src/`; the authorize URL is fetched from the API at runtime rather than constructed client-side. |
