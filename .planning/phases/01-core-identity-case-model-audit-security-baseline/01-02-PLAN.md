<objective>
Write the complete Rego policy bundle that is the system's single authorization brain, together with
its own unit-test suite. No TypeScript is written here — the policy is the deliverable.

Purpose: CONTEXT locks "Policy logic lives in Rego in OPA, not in TypeScript. Do not reimplement
ABAC in application code — TechArch chose OPA specifically to prevent three independently-buggy
implementations." `TechArch/04-security.md` §7.2 states the binding ABAC rules are "enforced in
policy, not scattered across handler code," and §8.5 adds that policy is "written once and versioned
like code, with its own test suite." Writing the policy first, as a standalone artifact with no
application dependency, is what makes that true rather than aspirational — and it means this plan
runs in wave 1 in parallel with the repository scaffold.

Output: A loadable OPA bundle at `policy/judicialsync/authz` exposing one decision entry point, and
a passing `opa test` suite covering every rule including the negative paths that Phase 1's success
criteria 1 and 4 depend on.
</objective>

**`rbac.rego` — Layer 1, coarse-grained.** From `TechArch/04-security.md` §7.2: "A request's role
determines which *endpoint classes* are even reachable … by route-level RBAC gate, before ABAC is
even evaluated."

Define `internal_only_route_prefixes := ["/api/v1/audit", "/api/v1/security", "/api/v1/retention",
"/api/v1/entitlements", "/api/v1/config"]` and the rule:

```rego
rbac_deny[reason] if {
    some role in input.principal.roles
    role.role_name == "attorney_external"
    count(internal_roles_held) == 0
    some prefix in internal_only_route_prefixes
    startswith(input.context.route, prefix)
    reason := "AUTH_SCOPE_DENIED"
}
```

This is the binding rule from §7.2 and `FRD/F00` Validation: "A principal with only
`attorney_external` role may never receive entitlements scoped to internal-only resources (ledger
write, calculation override, audit explorer), regardless of any case association." Note the
*regardless of any case association* — the rule must not consult case scope at all.

Also gate on MFA: `rbac_deny["AUTH_MFA_FAILED"] if { not input.principal.mfa_satisfied }`. CONTEXT:
"the application reads the `amr`/`acr` claim from the assertion and rejects sessions where MFA was
not satisfied. No dev bypass flag." Putting this in policy means no handler can forget it.

**`abac.rego` — Layer 2, fine-grained scope.** The requester's scope attributes
(court / division / case / proceeding / party_role / security_designation, per `FRD/F00`
Terminology) are matched against the resource's actual attributes.

Core rules:
- `in_court_scope` — true if the principal holds a `court` scope whose `scope_value` equals
  `input.resource.court_id`, **or** holds a `user_roles` entry whose `court_id` matches. A null
  `resource.court_id` (court-independent resource) does not auto-pass; require an explicit rule.
- `in_division_scope`, `in_case_scope`, `in_proceeding_scope` — same shape against the respective
  resource field, each only applied when the resource carries that field.
- `abac_deny["AUTH_SCOPE_DENIED"] if { input.resource.court_id != null; not in_court_scope }` —
  this is the cross-court isolation rule that `TechArch/00-overview.md` §159 requires
  ("court-level multi-tenancy by `court_id` enforced at the ABAC layer, not by physical
  separation") and that Phase 1's negative-path suite proves with two seeded courts.

**The hard constraint — role existence must never imply access.** CONTEXT states this as a hard
constraint, not a preference. Encode it structurally: the only rule that can produce `allow` is an
*entitlement* match, never a role match. Roles can only ever *deny* (the RBAC gate) or *scope*
(court/division affiliation). Write:

```rego
required_entitlement := data.judicialsync.authz.action_entitlement_map[input.resource.type][input.action]

entitlement_deny["AUTH_SCOPE_DENIED"] if {
    required_entitlement
    not required_entitlement in input.principal.entitlements
}
# Fail closed on an unmapped (resource.type, action) pair — a new resource type added in a later
# phase without a mapping entry is DENIED, not allowed.
entitlement_deny["AUTH_SCOPE_DENIED"] if { not required_entitlement }
```

Define `action_entitlement_map` as data in the same package covering only Phase 1 resource types —
CONTEXT: "Only Phase 1 entitlements are established. Do not invent complete cross-phase
permissions." Phase 1 map:

| resource.type | action | required entitlement |
|---|---|---|
| `case` | `read` | `case_read` |
| `case` | `create` | `case_create` |
| `case` | `update` | `case_update` |
| `security_designation` | `update` | `case_security_admin` |
| `proceeding` / `party` / `docket_event` / `document_reference` | `read` | `case_read` |
| `proceeding` / `party` / `docket_event` / `document_reference` | `create` | `case_update` |
| `audit_event` | `read` | `audit_reader` |
| `file` | `upload` | `file_upload` |
| `retention_schedule` | `read` | `retention_viewer` |
| `access_grant_request` | `create` | `access_admin` |
| `access_grant_request` | `approve` | `access_admin` |
| `encryption_key` | `rotate` | `key_custodian` |

Tests (`rbac_test.rego`, `abac_test.rego`) — at minimum:

- `test_role_without_entitlement_denied` — a principal with role `jury_admin`, correct court scope,

- The matching positive cases so the suite can distinguish "denies everything" from "denies correctly".

`policy/README.md` documents the input/output contract verbatim (it is the contract plan 01-07

  <name>Task 2: Write the security-designation rules including the Y2 principle 3 403-vs-404 decision</name>
  <files>policy/judicialsync/authz/designation.rego, policy/judicialsync/authz/designation_test.rego</files>
  <action>
`FRD/Y2-errors.md` principle 3 is **binding and already resolves the 403-vs-404 question** (CONTEXT:
"Do not re-litigate this"). Encode the test itself in policy so no handler re-decides it:

- **404 (existence-hiding)** on *blind-discovery* paths — "the requester has no other access path
  that already confirms the object/case exists."
- **403 (designation-denied)** where "the requester already has general, legitimate access to the
  parent case/object … and are only missing the *specific* sealed/restricted/grand-jury/juvenile
  entitlement."

Rules:

```rego
designation_entitlement_for := {
    "sealed":      "designation_sealed",
    "restricted":  "designation_restricted",
    "grand_jury":  "designation_grand_jury",
    "juvenile":    "designation_juvenile",
    "pii":         "designation_pii",
}

missing_designations[d] if {
    some d in input.resource.designations
    not designation_entitlement_for[d] in input.principal.entitlements
}

designation_deny if { count(missing_designations) > 0 }

# Y2 principle 3: does the requester already have a legitimate path to know this object exists?
has_parent_case_access if {
    input.resource.case_id != null
    "case_read" in input.principal.entitlements
    in_case_scope
}

hide_existence if { designation_deny; not has_parent_case_access }
```

The composed reason code follows `FRD/F00`/`FRD/F01`/`FRD/F02` Error States:
`AUTH_DESIGNATION_DENIED` (403) when `designation_deny` and `has_parent_case_access`;
`*_NOT_FOUND` (404) when `hide_existence`. Emit `reason_code` as
`"AUTH_DESIGNATION_DENIED"` or `"RESOURCE_NOT_FOUND"` and let plan 01-07's guard map
`RESOURCE_NOT_FOUND` to the per-resource 404 code (`CASE_NOT_FOUND`, `AUDIT_NOT_FOUND`, …).

Also encode the `FRD/F13` requirement that designation policy is configuration-driven, not
hardcoded: accept an optional `input.security_policies` array of
`{designation, required_entitlement}` rows (the Phase 1 `security_policies` table, read by plan
01-11) and prefer it over the built-in `designation_entitlement_for` default when present. This is
what makes `FRD/F13` Validation's "no designation policy may be altered via direct data edit outside
the configuration engine" meaningful, and it is the seam Phase 2's versioned configuration plugs
into without a policy rewrite.

Tests (`designation_test.rego`):
- `test_sealed_denied_403_when_requester_has_case_access` — principal holds `case_read` and matching
  case scope but not `designation_sealed` → `allow == false`, `reason_code == "AUTH_DESIGNATION_DENIED"`,
  `hide_existence == false`.
- `test_sealed_denied_404_when_blind_discovery` — same resource, principal holds neither `case_read`
  nor case scope → `hide_existence == true`.
- `test_sealed_allowed_with_entitlement`.
- `test_multiple_designations_requires_all` — a record tagged `["sealed","grand_jury"]` with only
  `designation_sealed` granted is denied.
- `test_security_policies_override` — an input `security_policies` row remapping `restricted` to
  `designation_restricted_v2` is honored over the built-in default.

  <files>policy/judicialsync/authz/sod.rego, policy/judicialsync/authz/decision.rego, policy/judicialsync/authz/sod_test.rego, policy/judicialsync/authz/decision_test.rego, scripts/opa-test.sh, .github/workflows/policy.yml</files>

**`sod.rego`.** From `TechArch/04-security.md` §7.2: "`system_admin` and `security_officer` may not
approve a privileged role-grant request they themselves created — enforced as a policy rule
comparing `request.created_by` against `request.approved_by`, **not an application-layer `if`
statement that a future refactor could drop**." CONTEXT reinforces: "Prefer 'the API refuses' over
'the audit catches it'."

```rego
sod_deny["AUTH_SOD_VIOLATION"] if {
    input.action == "approve"
    input.resource.requested_by != null
    input.resource.requested_by == input.principal.user_id
}
```

Keep it resource-type-agnostic (it keys off `action == "approve"` and the presence of
`resource.requested_by`) so Phase 2's configuration publish (F03, `drafted_by != approved_by`) and
Phase 5's template application reuse the identical rule with no policy change. Document that in a
comment.

**`decision.rego` — the single entry point.** Plan 01-07's guard calls exactly one path:
`POST /v1/data/judicialsync/authz/decision`.

```rego
default decision := {"allow": false, "reason_code": "AUTH_SCOPE_DENIED", "hide_existence": false}

all_denials := rbac_deny | abac_deny | entitlement_deny | sod_deny

decision := {"allow": false, "reason_code": "RESOURCE_NOT_FOUND", "hide_existence": true} if {
    hide_existence
}

decision := {"allow": false, "reason_code": reason, "hide_existence": false} if {
    not hide_existence
    count(all_denials) > 0
    reason := highest_precedence_reason
}

decision := {"allow": true, "reason_code": "", "hide_existence": false} if {
    count(all_denials) == 0
    not designation_deny
}
```

Reason precedence (most specific wins, so the client gets the most actionable code):
`AUTH_SOD_VIOLATION` > `AUTH_DESIGNATION_DENIED` > `AUTH_MFA_FAILED` > `AUTH_SCOPE_DENIED`.

**The `default decision` must be deny.** This is the Rego-level expression of `FRD/Y2-errors.md`
principle 1 ("Fail closed, not open") — a malformed or partial input produces deny, never an
undefined result the guard might mistake for allow.

Tests (`decision_test.rego`):
- `test_default_is_deny_on_empty_input` — `decision with input as {}` yields `allow == false`.
- `test_default_is_deny_on_malformed_input` — input missing `resource` yields `allow == false`.
- `test_full_allow_path` — a correctly entitled, in-scope, MFA-satisfied principal on a non-designated
  resource yields `allow == true`.
- `test_precedence_sod_over_scope` — a self-approval attempt that is *also* out of scope reports

- `test_hide_existence_wins_over_other_denials` — a blind-discovery sealed request reports

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API→PDP | The authorization request document crossing from the NestJS guard into OPA; a malformed or attacker-influenced document must not produce an allow. |
| policy→API | The decision document crossing back; an undefined or partial result must not be read as allow. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Elevation of privilege | `policy/judicialsync/authz/decision.rego` returning undefined for an input shape the rules do not match, which a caller could misread as allow | mitigate | `default decision := {"allow": false, ...}` is declared in `decision.rego`; `decision_test.rego::test_default_is_deny_on_empty_input` and `test_default_is_deny_on_malformed_input` assert it. |
| T-01-05 | Information disclosure | `policy/judicialsync/authz/designation.rego` returning a 403-shaped denial on a blind-discovery path, leaking the existence of a sealed matter | mitigate | `hide_existence` rule in `designation.rego` gates on `has_parent_case_access`; `decision.rego` gives the hide-existence branch precedence over all other denial branches so the error code cannot differ by denial cause; asserted by `test_hide_existence_wins_over_other_denials`. |
