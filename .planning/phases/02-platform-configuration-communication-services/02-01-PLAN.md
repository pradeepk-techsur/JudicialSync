<objective>
Create every database object Phase 2 needs, in one plan, so that the twelve plans that follow each
work inside their own module directory and never contend for `schema.prisma`, `app.module.ts`, or
`.env.example`.

Purpose: Phase 2 delivers three services (F3 Configuration Engine, F4 Notifications, F5 Search) whose
guarantees are all structural — a published configuration that cannot be edited, an approval that
cannot be self-granted, an index row that cannot be more permissive than the record it describes.
Every one of those guarantees is cheapest and strongest at the database layer, which is the stance
Phase 1 took for audit immutability (`TechArch/04-security.md` §7.3: "not because the ORM forbids it,
but because PostgreSQL itself will reject the statement regardless of which code path generated it").
This plan also performs the single migration CONTEXT insists be taken now, while the system is
pre-pilot: `audit_events.rule_package_version_id`, with the canonical hashed field list made
**explicit and itself versioned** so Phase 1's integrity-verification job does not report a false
chain break across the migration boundary.

Output: four migrations, the Prisma models, the three new NestJS module placeholders registered on
the composition root, the complete Phase 2 environment surface, and a test proving the four
structural guarantees hold at the database level.
</objective>

Third, published-package immutability. `FRD/F03` Process step 4 requires "the prior version remains
retrievable (never overwritten)", and ROADMAP criterion 1 requires it be true after a new publish.
Phase 1 proved immutability by `REVOKE` because `audit_events` is append-only in full; a rule package
is *mutable while it is a draft* and immutable once published, so the guard is a trigger, not a grant:

```sql
CREATE OR REPLACE FUNCTION platform.rule_package_versions_immutable_published()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
  IF TG_OP = 'UPDATE' AND OLD.status = 'published' THEN
    RAISE EXCEPTION 'CONFIG_IMMUTABLE: published rule package version % cannot be modified', OLD.id
      USING ERRCODE = '42501';
  END IF;
  IF TG_OP = 'DELETE' AND OLD.status = 'published' THEN
    RAISE EXCEPTION 'CONFIG_IMMUTABLE: published rule package version % cannot be deleted', OLD.id
      USING ERRCODE = '42501';
  END IF;
  RETURN COALESCE(NEW, OLD);
END $$;

CREATE TRIGGER trg_rule_package_versions_immutable
  BEFORE UPDATE OR DELETE ON platform.rule_package_versions
  FOR EACH ROW EXECUTE FUNCTION platform.rule_package_versions_immutable_published();
```

Apply the same trigger shape to `workflow_state_defs`, `threshold_defs` and `event_mapping_defs` —
reject any UPDATE or DELETE whose `rule_package_version_id` belongs to a published row.

Fourth, the approval record. CONTEXT's locked **deviation from `Y1a-api-shared.md`** is that the
approver "must act in their own authenticated session" and the endpoint "rejects any
`approving_user_id` supplied in the request body". The session id is therefore part of the permanent
record, and `drafted_by <> approved_by` is a database CHECK, not an application `if`:

```sql
CREATE TABLE platform.rule_package_approvals (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  rule_package_version_id UUID NOT NULL UNIQUE REFERENCES platform.rule_package_versions(id),
  drafted_by UUID NOT NULL REFERENCES platform.users(id),
  approved_by UUID NOT NULL REFERENCES platform.users(id),
  approver_session_id UUID NOT NULL REFERENCES platform.sessions(id),
  required_entitlement TEXT NOT NULL,
  approved_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT rule_package_approvals_sod CHECK (drafted_by <> approved_by)
);
CREATE INDEX idx_rule_package_approvals_version ON platform.rule_package_approvals(rule_package_version_id);
```

`TechArch/04-security.md` §7.2 states the maker-checker rule is "enforced as a policy rule comparing
`request.created_by` against `request.approved_by`, not an application-layer `if` statement that a
future refactor could drop." The OPA policy still decides; this CHECK is the backstop behind it,
following Phase 1's "dangerous guard first" pattern.

```sql
CREATE OR REPLACE FUNCTION platform.compute_audit_row_hash_v2(
  p_actor_id UUID, p_action_type TEXT, p_object_type TEXT, p_object_id UUID,
  p_before_state JSONB, p_after_state JSONB, p_rule_version_ref UUID,
  p_calculation_version_ref UUID, p_rule_package_version_id UUID,
  p_client_ip TEXT, p_session_id UUID, p_occurred_at TIMESTAMPTZ,
  p_hash_field_list_version SMALLINT, p_prev_hash TEXT
) RETURNS TEXT LANGUAGE sql IMMUTABLE AS $$
  SELECT encode(digest(
    -- EXACT v1 field order and delimiter, copied from migration 20260101000200, then the two v2 fields.
    ... || '|' || coalesce(p_rule_package_version_id::text,'')
        || '|' || p_hash_field_list_version::text
        || '|' || p_prev_hash,
    'sha256'), 'hex');
$$;
```

Including `hash_field_list_version` **inside** the v2 payload is deliberate: without it, a compromised
application instance could write a new row declaring version 1, compute a v1 hash that omits
`rule_package_version_id`, and thereby strip the provenance stamp while keeping the chain consistent.
Close that downgrade path at both ends — the field is hashed, **and** insertion of anything other than
the current version is rejected:

```sql
CREATE OR REPLACE FUNCTION platform.audit_hash_field_list_required_on_insert()
RETURNS SMALLINT LANGUAGE sql IMMUTABLE AS $$ SELECT 2::smallint $$;
```

Replace the `BEFORE INSERT` trigger function so that it:
1. Raises `ERRCODE 42501` unless `NEW.hash_field_list_version = platform.audit_hash_field_list_required_on_insert()` — no new row may claim an older field list.
