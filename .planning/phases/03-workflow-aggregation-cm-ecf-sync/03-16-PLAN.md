<objective>
Ship the Case Timeline and Screen-18's CM/ECF Adapter Health panel, rendering the phase's two opposite
absence semantics correctly and keeping conflict resolution in exactly one place.

Purpose: ROADMAP criterion 3 is a user-visible claim — a merged, filterable chronological view with deep
links into each underlying record. The subtle part is what the screen does about missing data. CONTEXT is
explicit that the two kinds point in opposite directions: a **designation-excluded entry is invisible**
(no placeholder, no count, no hint — security), while an **unavailable provider is loudly announced** (a
prominent Alert naming the missing sources — safety). An authorized user must never mistake a partial
timeline for a complete one; an unauthorized user must never learn that something was withheld. The API
already separates them; this plan is where they could be re-merged by a well-meaning "N items hidden"
line, so the component that renders the loud case is forbidden from mentioning the silent one.

Screen-18 carries the second structural decision: its conflict list **deep-links into the Exception
Queue's triage row**. F10 step 5 routes conflicts into F07, so sync-conflict resolution is built once and
this panel points at it. Shipping a second set of accept/keep radios here would be two implementations of
the most consequential decision in the adapter.

Output: the timeline page with its filters, deep links and partial-data Alert; the case-list inbound
link; Screen-18's three panels; and Playwright coverage of both absence semantics and the truthful
outbound indicator.
</objective>

**`CaseTimelinePage.tsx`** consumes `GET /cases/{id}/timeline` through TanStack Query:
- A USWDS **Collection** (`usa-collection`) rendering the chronological list — not a table. The entries
  are heterogeneous narrative items with a timestamp, a summary and a link, which is exactly what the
  Collection component is for, and it reflows at mobile widths without the stacked-card treatment a
  table needs.
- Each item renders: the timestamp formatted in the court's local zone (date only when
  `precision: "date"`, so the UI never invents a time the docket did not state), a neutral USWDS Tag
  carrying the `entry_type` as **text** (`Docket event`, `Hearing`) with no colour coding by type, the
  summary, and a `View record` link to the entry's `deep_link`.
- Order is the server's. **Do not re-sort client-side** — the deterministic three-key order is the
  server's guarantee and a client sort would quietly break the same-day sequencing F08 requires.
- `TimelineFilterBar.tsx`: USWDS Selects/checkboxes for Event type (populated from the entry types
  present plus the server's declared set), Module, and a date-range pair. `Apply filters` is the
  page-level primary; `Clear filters` is unstyled. An inverted range is caught client-side before the
  request and also renders the server's `TIMELINE_INVALID_RANGE` message if it arrives.
- A `Show candidate items` checkbox mapping to `include_candidates`, with helper text
  `Candidate items are proposed and not yet reviewed.` It is wired and currently changes nothing, which
  is correct — F08 requires the view reflect confirmed state by default, and Phase 7 supplies the
  content.

**`PartialDataAlert.tsx` — the loud half, and the only place absence is ever mentioned.**
- Renders **only** when the response's `partial` is `true`.
- A USWDS Alert with `type="warning"`, `role="alert"`, rendered **above** the list so it cannot be
  scrolled past: heading `This timeline is incomplete`, body
  `The following sources did not respond and their entries are missing: {names}. Reload to try again.`
  Names come from the `providers` block's `unavailable` entries, mapped through a small label table
  (`speedytrial` → `Speedy Trial`, `evidentiary` → `Evidentiary`, `docket` → `Docket`, `shared` →
  `Hearings`).
- **It must never mention sealed, restricted, excluded, withheld or redacted content, and must never
  render a count of anything missing for an authorization reason.** A grep gate in `<verify>` asserts
  those words do not appear in the file. Put the reason in a file comment: designation exclusion is
  silent by contract, and a single sentence here conflating the two would leak the existence of sealed
  entries to exactly the user who must not learn of them.
- When `partial` is `false` the component returns `null`. There is no "all sources responded" banner —
  completeness is the unremarkable case and announcing it would train users to ignore the Alert.

**Empty state.** A rendered Alert, never a blank region: `No timeline entries` /
`This case has no docket events or hearings in the selected range.` The **same text renders whether or
not entries were designation-excluded** — this is Phase 2's byte-identical empty state applied to the
timeline, and it is the second half of the silent-exclusion property.
