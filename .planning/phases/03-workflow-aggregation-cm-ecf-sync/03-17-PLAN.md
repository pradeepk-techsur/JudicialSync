<objective>
Ship the de-identified reporting dashboard with its permanently visible human-in-command label, and
extend the build-blocking accessibility gate to all five Phase 3 screens.

Purpose: ROADMAP criterion 4 is a user-visible claim — a court administrator views a role-limited,
de-identified operational dashboard containing no path back to an individual judicial determination.
Plans 03-01 and 03-08 made the de-identification a database property; this plan is where it is seen, and
where the two things that can only fail in the browser are got right. First, the label: PROJECT.md calls
human-in-command non-negotiable, F09 step 5 requires a persistent UI label, and CONTEXT extends it into
export bytes — so on screen it must be **permanently visible**, not a tooltip and not behind a collapsed
panel. Second, suppression: a suppressed cell must say so. A blank reads as "no data" and a zero is a
false statement, and either would quietly undo the small-cell protection by making a reader draw the
wrong inference.

This plan also closes the phase's accessibility commitment: **the axe-core CI gate extends to all five
Phase 3 screens and continues to BLOCK the build.** Report-only was rejected in Phase 1 — a warning
nobody must act on gets ignored — and `Y2-accessibility.md` calls the automated gate a release gate, not
a backlog item.

Output: the dashboard, the export download through the app's own API, the consolidated axe gate, and the
CI wiring that makes it blocking.
</objective>

- It also renders in the page's `<h1>`-adjacent region on mobile, because `Y1-responsive.md` requires
  reflow without loss of content and a label scrolled off a narrow screen is a lost control.

**`ReportingDashboardPage.tsx`:**
- A scope control (Court / Division select, limited to the principal's authorized scopes) and a date
  range, then `Apply` as the page-level primary.
- Four stacked `MetricSetSection`s with `h2` headings, each rendered **only** when the API returned that
  set: Backlog age, Exception volume, Adoption rate, Configuration consistency. An in-page jump list of
  anchor links sits under the label so a keyboard user reaches a section without tabbing through tables.
- `alert_effectiveness` is not offered in the scope control at all. If the API returns
  `422 REPORT_INVALID_METRIC_SET`, render the server's message in an `ApiErrorAlert` — never an empty
  section, which a reader would misread as "no alerts failed".

  carries no identifiers. Add a comment saying the absence is deliberate, so nobody "fixes" it later.

  mobile widths. Age renders as the bucket string from the API (`0-2d`, `3-7d`, `8-30d`, `30d+`) — **never
  reformatted into an exact duration**, which would re-introduce the quasi-identifier the buckets exist
  to remove.
- **`SuppressedCell.tsx`** renders for any row whose `suppressed` is true: the word `Suppressed` as

  threshold comes from the response's `min_cell_count`. Never a blank cell, never `0`, never a dash.
- Empty state, as a rendered Alert: `No metrics for this scope and period` /
  `Adjust the scope or widen the date range.`
- `403 REPORT_ACCESS_DENIED` and `403 REPORT_SCOPE_DENIED` render the server's messages through
  `ApiErrorAlert`; the page shows no metric shell behind them.

**`ExportButton.tsx` — the bytes go through our own API.** A format select (CSV / JSON) and an `Export`
outline button that:
- issues an **authenticated same-origin `fetch`** to `GET /api/v1/reporting/export` with the current
  query, through the generated client so credentials and error handling match every other call;
- reads the response as a `Blob`, creates an object URL, clicks a synthesized anchor carrying the
  `download` filename parsed from `Content-Disposition`, and revokes the URL;
- **never** navigates the browser to a URL, never uses a presigned link, and never references any
  storage service address. A grep gate asserts no `minio`, `s3`, `presign` or absolute URL appears in the
  file. The reason is concrete: a plain navigation would not carry the session, and a store URL is not
  resolvable from the browser at all.
- is `aria-disabled` with visible helper text `Preparing export…` while a request is in flight, per the
  contract's blocked-control pattern, and announces completion through an `aria-live="polite"` region.
