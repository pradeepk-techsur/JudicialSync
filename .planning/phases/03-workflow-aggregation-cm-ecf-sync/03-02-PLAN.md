<objective>
Extend the single OPA policy bundle with every authorization fact Phase 3's eleven API plans need, before
any of those plans writes a controller.

Purpose: plan 01-02 made an unmapped `(resource.type, action)` pair a **deny** — "a new resource type added
in a later phase without a mapping entry is DENIED, not allowed" — and declared `policy/**` owned by one
plan so later plans add rows here rather than editing the bundle themselves. Phase 3 adds roughly a dozen
routes; without this plan every one of them returns a silent 403 and eleven plans debug the same cause.
Doing it first, in wave 1, also lets the policy carry two of Phase 3's locked decisions in their proper
home: **ownership resolves by entitlement, not role** (so the policy reads the entitlement the row itself
declares), and **outbound docket filing ships as a provable refusal** (so the deny is a policy rule, not an
`if` statement in a handler a future refactor could drop).

Output: the Phase 3 rows of `action_entitlement_map`, a dynamic entitlement rule for `task` and `exception`
resources, an unconditional outbound deny, a declared entitlement catalog including the non-grantable set,
and table-driven tests that cannot drift from the map.
</objective>

<feature_dependencies>
Implements: F6: Work Queue (task authorization), F7: Exception Queue (exception authorization), F8: Case Timeline (timeline read authorization), F9: Operational Reporting Feed (`reporting_viewer` gate), F10: CM/ECF Integration Adapter (adapter admin gate and the outbound refusal)
Depends on: F0: Identity and Access Management — plan 01-02's `decision.rego`, `rbac.rego`, `abac.rego`, `designation.rego`, `sod.rego` and their `action_entitlement_map`, plus plan 01-07's global ABAC guard and `ResourceLoaderService`
Enables: F6, F7, F8, F9, F10 — every Phase 3 controller route is reachable only because its pair is mapped here
</feature_dependencies>

# Revisit only against a contract a court has validated (F19/Phase 6 or F24/v2).
outbound_deny["CMECF_OUTBOUND_DENIED"] if {
    input.resource.type == "cmecf_outbound"
}

Place `CMECF_OUTBOUND_DENIED` **first** in `highest_precedence_reason`, ahead of
`AUTH_SOD_VIOLATION`: it is the most specific and most actionable code — a principal told
"you are not authorized to submit outbound docket references" learns the capability does not exist,
whereas `AUTH_SCOPE_DENIED` would suggest an entitlement might fix it. The resulting order is
`CMECF_OUTBOUND_DENIED > AUTH_SOD_VIOLATION > AUTH_DESIGNATION_DENIED > AUTH_MFA_FAILED >
AUTH_SCOPE_DENIED`. Existence-hiding still wins over everything, as 01-02 wrote it — an outbound
attempt against a sealed object must not report a different code than against an unsealed one.

Do not invent a second composition mechanism; read `decision.rego` and extend the expression it
already has.
