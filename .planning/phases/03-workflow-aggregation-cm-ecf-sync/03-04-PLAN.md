<objective>
Add exactly one container to the Compose stack — a fixture-driven CM/ECF stand-in the adapter talks to over
real HTTP — and write down the wire contract it implements as an explicit, unvalidated assumption.

Purpose: CONTEXT rejected both alternatives by name. File-drop ingestion leaves the polling loop,
pagination, transport auth, retry and backoff unbuilt — "the parts most likely to be wrong against a real
endpoint". An in-process test double is "the stub Phases 1 and 2 refused five times; it becomes the only
exercised path". This is the MinIO-for-S3 and Keycloak-for-court-IdP pattern applied a third time: the
protocol is genuine, only the system on the other end is local, and pointing at a court's real endpoint is
a provider plus mapper swap.

The container must be **drivable**, because ROADMAP criterion 5 says the conflict behaviour is *"confirmed
by deliberately creating a conflicting field"* — a fixture you cannot steer proves nothing. Four scenarios
must be reachable from a test: a field-level conflict, a duplicate redelivery, a malformed record, and a
total outage.

Output: the container, its fixtures for the two seeded courts, a control API, a typed Jest helper, the
documented fixture contract carrying F10's `[ASSUMPTION]` forward, and a contract test proving the mock
itself behaves as documented before any adapter code depends on it.
</objective>

**Write the contract first, in `docs/CMECF-FIXTURE-CONTRACT.md`,** because the adapter codes against this
document and not against the implementation. Open it with the marker verbatim, carrying F10's own
`[ASSUMPTION]` forward rather than resolving it:

> `[ASSUMPTION]` No real CM/ECF interface specification is available (FRD F10, TechArch §9.1, FRD Y3 all
> flag this). The contract below is **invented for development** and must be validated against a real
> court deployment before pilot. The adapter is built behind `CmecfSyncProvider` so a court's actual
> transport and schema land as a provider plus mapper swap, not a rewrite.

Then specify, exactly:

```
GET /cmecf/v1/records
  Query:   court_code (required), since (cursor, optional), limit (1..500, default 100)
  Headers: Authorization: Bearer <token>        (required)
           X-Idempotency-Key: <uuid>            (required; echoed back in X-Idempotency-Key)
  200 {
    records: [{
      source_identifier: string,   // CM/ECF-native, stable, unique within the court
      object_type: "case" | "party" | "docket_event" | "order" | "document_reference",
      updated_at: string,          // RFC3339 UTC
      superseded: boolean,         // CM/ECF reports a record as replaced; never a delete
      payload: object              // per-type field map; see the per-type tables below
    }],
    next_cursor: string | null,
    has_more: boolean
  }
  401 { error_code: "UNAUTHORIZED", message: string }     // missing or wrong bearer token
  503 { error_code: "FEED_UNAVAILABLE", message: string } // outage scenario

GET /healthz -> 200 { ok: true }    (compose healthcheck; never gated by the outage scenario)
```

Per-type `payload` field tables, each naming the `Y0a` column it maps onto:
- `case` → `case_number`, `case_caption`, `case_type`, `division_code`
- `party` → `case_source_identifier`, `party_name`, `party_role`
- `docket_event` → `case_source_identifier`, `event_code`, `event_description`, `event_date`
- `order` → `case_source_identifier`, `document_title`, `entered_at` — **and the mapping note**: `Y0a`
  has no `orders` table, so an `order` projects onto a `document_references` row plus its
  `docket_events` row. Mark that mapping itself `[ASSUMPTION]`.
- `document_reference` → `case_source_identifier`, `document_title`, `storage_pointer`

Add a **cross-court identifier note**: CM/ECF `source_identifier` values are unique within a court, but
`docket_events` carries `UNIQUE (source_system, source_identifier)` globally. The adapter therefore
namespaces on ingest as `{court_code}:{cmecf_source_identifier}`. State this is the adapter's convention,
not CM/ECF's, and that plan 03-10 implements it.

**`infra/mock-cmecf/server.mjs`** — Node 20, **zero npm dependencies**, built on `node:http` so the image
builds in seconds and adds no supply-chain surface to a federal stack. It:
- Loads `fixtures/*.json` at boot into an in-memory record list keyed by `court_code`.
- Serves `GET /cmecf/v1/records` per the contract: validates the bearer token against
  `CMECF_API_TOKEN`, returns `401` when absent or wrong; slices by `since` cursor and `limit`, setting
  `next_cursor` to the last returned record's cursor and `has_more` accordingly; echoes
  `X-Idempotency-Key`; returns `400` when it is missing, so the adapter is forced to send one.
- Serves `GET /healthz` unconditionally.
- Serves a **control API**, reachable only from inside the compose network (bind the control routes to the
  same port but require header `X-Mock-Control: 1`; document that this container is never deployed):
  - `POST /__control/reset` — restore the baseline fixtures and scenario `healthy`.
  - `POST /__control/scenario {"name": "healthy"|"conflict"|"duplicate"|"malformed"|"outage"}`
  - `POST /__control/records {record}` — append or replace one record by `source_identifier`.
  - `GET  /__control/state` — current scenario and record count, for test diagnosis.

Scenario semantics, each chosen to exercise one locked decision:
| scenario | behaviour |
|---|---|
| `healthy` | Baseline fixtures, normal pagination. |
| `conflict` | The next feed emits a `party` record for the seeded conflict case whose `party_name` differs from the local value. Combined with plan 03-13's seeded locally-modified field, this is ROADMAP criterion 5's "deliberately creating a conflicting field". |
| `duplicate` | The feed re-emits the previous page **byte-identical**, same `source_identifier` and same payload, so the adapter's hash comparison is the only thing that can distinguish it. |
| `malformed` | One record in the page omits `source_identifier`; one carries an `event_date` that is not a date. The page still contains valid records, so the adapter must reject per record and not drop the page. |
| `outage` | Every `/cmecf/v1/records` request returns `503 FEED_UNAVAILABLE`. `/healthz` stays `200` so Compose does not restart the container mid-test. |

**`infra/mock-cmecf/Dockerfile`** — `FROM node:20-alpine` (pinned, never `:latest`), copy `server.mjs` and
`fixtures/`, `EXPOSE 8099`, `USER node`, `CMD ["node","server.mjs"]`. No package install step.

**Fixtures** — `court-a-baseline.json` and `court-b-baseline.json`, keyed to plan 01-04's two seeded

prominent "this container is a development fixture and is never deployed" banner.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| external feed→adapter | Records from a system outside the trust boundary entering the platform; in development this container stands in for a federal court's authoritative docket |
| test→mock control API | Test-controlled strings steering the fixture's behaviour |
| compose network→host | Container ports and credentials crossing out of the development stack |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-19 | Spoofing | An unauthenticated caller reading the record feed, leaving the adapter's transport auth untested | mitigate | `infra/mock-cmecf/server.mjs` validates the bearer token against `CMECF_API_TOKEN` on `/cmecf/v1/records` and returns 401 without it; `mock-cmecf-contract.e2e-spec.ts` asserts both the missing-token and wrong-token cases |
| T-03-20 | Elevation of privilege | The `__control` scenario API reachable from outside the development stack | mitigate | Port 8099 is not published to the host by default in `docker-compose.yml`; control routes require the `X-Mock-Control` header; `infra/mock-cmecf/README.md` and the Dockerfile comment state the container is never deployed |
| T-03-21 | Information disclosure | A development bearer token committed and later reused in a real environment | mitigate | `.env` carries `devtoken-local-only` with a comment pointing at `TechArch/05-tech-stack.md` §8.4's secrets manager; `.env.example` (plan 03-01) carries the key with no value; the token grants access only to a fixture container |
| T-03-22 | Tampering | A fabricated schema hardening into an unexamined assumption before a court validates it | mitigate | `docs/CMECF-FIXTURE-CONTRACT.md` opens with the `[ASSUMPTION]` marker and plan 03-14 copies it into `docs/ASSUMPTIONS.md`; the adapter is built behind `CmecfSyncProvider` so the swap is a provider plus mapper |
| T-03-23 | Denial of service | An unbounded `limit` causing the adapter to pull an entire docket in one request | mitigate | `server.mjs` clamps `limit` to `1..500`; plan 03-03's `cmecfPolicySchema` bounds `max_records_per_poll` to `[1, 5000]` and plan 03-10's poller honours the cursor |
</threat_model>
