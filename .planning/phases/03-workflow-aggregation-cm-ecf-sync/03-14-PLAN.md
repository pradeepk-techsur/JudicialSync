<objective>
Correct the published contract to describe what Phase 3 actually built, register every deviation and
assumption, and regenerate the typed client the three UI plans will compile against.

Purpose: the phase's governing rule, inherited from Phase 2 and restated in CONTEXT, is that **deviating
from spec is fine; deviating silently is not — correct the contract and register it.** Phase 3 carries
eight deviations, two of which change an endpoint's meaning (`/tasks/{id}/complete` is no longer
user-invokable, `/integrations/cmecf/sync` no longer carries records). A generated client built from an
uncorrected contract would hand the UI plans operations that do not exist and omit response shapes they
must render — the timeline's 206, the reporting payload's required label.

This plan runs before the UI plans for the same reason plan 02-12 ran before plans 02-13 to 02-15: the
screens consume the generated client, and a client regenerated after the screens are written is a
rewrite rather than a contract.

Output: the emitted and committed OpenAPI contract, the eight registered deviations, the three carried
assumptions, a consolidated error-code catalog, the regenerated client, and a CI gate that fails on drift.
</objective>
