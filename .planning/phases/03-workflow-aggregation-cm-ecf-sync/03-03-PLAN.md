<objective>
Put every Phase 3 configurable number, and the one validator that enforces the phase's most-cited rule,
into the shared zod package both the server and the client already import.

Purpose: three Phase 3 decisions are *"court-configurable, with a hard floor configuration cannot go
below"* — the rationale bar, the small-cell suppression k, and the queue aging thresholds. A floor is only
real if a rule package attempting to go below it is **rejected at publish**, which means the floor lives
in the same zod refinement layer that already rejects threshold gaps and ambiguous mappings. And CONTEXT
locks **one shared validator** for exception resolution (`EXCEPTION_RATIONALE_REQUIRED`,
`EXCEPTION_RATIONALE_TOO_SHORT`) and task dismissal (`TASK_RATIONALE_REQUIRED`) precisely so the two bars
cannot drift — which only holds if there is literally one function.

This is a TDD plan: every rule here is a pure function over a value with a defined input and output, which
is exactly the `expect(fn(input)).toBe(output)` shape, and these are the rules two later screens and four
later services will trust without re-deriving.

Output: four new modules in `@judicialsync/config-schema`, their refinements composed into the operational
package schema so `validateRulePackage` rejects out-of-bounds drafts, and a test suite that fixes the
floors as behaviour.
</objective>

  <behavior>
**`validateRationale(value, bar)` — the one validator.** Pure, browser-safe, no I/O.

| input | bar | expected output |
|---|---|---|
| `undefined` / `null` / `""` / `"   "` | any | `{ code: "RATIONALE_REQUIRED" }` |
| `"too short"` (9 chars, 2 words) | `{min_characters:10,min_words:2}` | `{ code: "RATIONALE_TOO_SHORT", min_characters:10, min_words:2, actual_characters:9, actual_words:2 }` |
| `"corrected"` (9 chars, 1 word) | `{10,2}` | `RATIONALE_TOO_SHORT` |
| `"supersedingvalue"` (16 chars, 1 word) | `{10,2}` | `RATIONALE_TOO_SHORT` — the word rule is independent of the character rule |
| `"party name corrected"` | `{10,2}` | `null` |
| `"  party name corrected  "` | `{10,2}` | `null` — length and word count are measured after trimming |
| `"party name corrected"` (20 chars, 3 words) | `{40,2}` | `RATIONALE_TOO_SHORT` — a court may tighten |
| any | `{5,1}` | **throws** — `validateRationale` rejects a bar below `RATIONALE_HARD_FLOOR`, so a caller cannot smuggle a weaker bar past it |

Words are `btrim(value).split(/\s+/)` filtered for empties — the same definition as the database trigger
in plan 03-01 (`regexp_split_to_array(btrim(...), '\s+')`). The spec file asserts that parity in a comment
and in one test with a multi-space string, because two definitions that diverge would let the application
accept what the database then rejects.

**`queuePolicySchema`** — a zod object with these refinements:
- `rationale_bar.min_characters >= RATIONALE_HARD_FLOOR.min_characters` and
  `rationale_bar.min_words >= RATIONALE_HARD_FLOOR.min_words`, each failing with
  `CONFIG_INVALID_STRUCTURE` and a message naming the floor. **A draft setting `min_characters: 1` is
  rejected at publish.**
- `legally_significant_task_types` must be a superset of `LEGALLY_SIGNIFICANT_TASK_TYPES_BASELINE`;
  omitting any baseline member fails with `CONFIG_INVALID_STRUCTURE` naming the missing types.
  (Discretion resolved: config-driven **with** a non-removable baseline, the same tighten-yes-weaken-no
  shape used twice elsewhere in this phase.)
- `task_aging_threshold_hours` in `[1, 8760]`.
- `exception_aging_threshold_hours_by_severity` requires all four severities present, each in `[1, 8760]`,
  and **strictly non-increasing** from `low` to `critical` — a configuration where a critical exception
  may age longer than a low one is a structural error, not a preference.
- `completed_task_retention_days` in `[30, 3650]` (discretion resolved: default 90).

**`reportingPolicySchema`** — `min_cell_count >= REPORTING_MIN_CELL_HARD_FLOOR` (5), `<= 1000`;
`enabled_metric_sets` must be a subset of `V1_METRIC_SETS`; a draft naming `alert_effectiveness` is
rejected with `CONFIG_INVALID_STRUCTURE` and a message saying it arrives in Phase 8.
Carry a literal `[ASSUMPTION]` comment on the default k verbatim:
`// [ASSUMPTION] Default small-cell threshold k = 5 has no stakeholder validation. Flagged for pilot.`
Plan 03-14 copies that marker into `docs/ASSUMPTIONS.md`.

**`cmecfPolicySchema`** — `poll_interval_seconds` within `POLL_INTERVAL_BOUNDS_SECONDS` (60..86400,
default 300); `max_records_per_poll` in `[1, 5000]`; `sustained_failure_consecutive_cycles` in `[1, 100]`
(default 3); `sustained_failure_minutes_without_success` in `[5, 10080]` (default 60); and a refinement
that `sustained_failure_minutes_without_success >= 2 * (poll_interval_seconds / 60)` so a court cannot
configure a definition that fires on a single missed cycle.

**Composition.** `package-types.ts` adds `queue_policy`, `reporting_policy` and `cmecf_policy` to the
**operational** rule-package snapshot schema (not the security/retention package — these are operational
rules, approved by `config_admin`). `error-codes.ts` gains `TASK_RATIONALE_TOO_SHORT` alongside the
existing `TASK_RATIONALE_REQUIRED` / `EXCEPTION_RATIONALE_*` constants, so the three call sites share
string constants rather than literals. `index.ts` re-exports everything named in the contracts above.

**Package purity.** The package must stay importable from the React bundle: no `fs`, no `pg`, no
`@prisma/client`, no NestJS import anywhere under `packages/config-schema/src/`.
  </behavior>
